# 分析报告框架

数字必须能从 `reviews_master` 透视回去。抬头写清样本边界：ASIN 数、评论数、下载覆盖率、排除规则、未覆盖的头部品牌/ASIN。

主分析默认：`flag_accessory_model` 为空。非美评论保留，切片时单独看。

## 1. 评论总结

每张卡约 200 字，写判断而不是堆例子。

1. 好评亮点
2. 差评痛点
3. 买家期待
4. 人群画像
5. 使用场景
6. 购买理由

每张卡用一级+二级的频次托底，可点 1–2 条原话作证据，不要写成摘录清单。

## 2. 详细分析

用一级作节、二级作条目，条目旁标注命中条数。

1. 买家喜欢什么
2. 差评主要抱怨什么
3. 哪些人群/场景更合适
4. 哪些情况不适合
5. 买家希望哪里更好
6. 值不值这个价

每个二级给：一句话判断 + 1 条代表性原文。人群/场景/不适合从摘录里归纳，不要脱离文本编造。

## 3. 产品方向

同样用一级+二级。

1. 产品亮点分析：已验证、可写成卖点/FAQ 的二级
2. 产品痛点 & 新品方向：高频差评二级 → 可跟进的改款/新品命题

## 4. 源表字段切片

- 评分：数量、星级、赞同数
- 产品：品牌、型号、ASIN
- 类型：VP、Vine
- 内容形态：纯文本 / 有图 / 有视频
- 其他：国家、评论时间

有明确产品类型对标时，再做品牌技术栈（LiDAR / RTK / Vision / 有线）和头部 ASIN 把脉。切片结论不得写成全类目普查，除非样本覆盖已经声明为全量。
